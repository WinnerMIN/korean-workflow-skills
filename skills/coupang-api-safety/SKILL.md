# 쿠팡 파트너스 Open API 안전 규칙

쿠팡 파트너스 API는 짧은 시간에 호출이 몰리면 경고가 쌓이고, 경고가 누적되면 API 이용이 제한된다. 이 스킬은 그런 제한을 피하도록 호출 코드를 만들 때 지켜야 할 규칙을 정리한 것이다.

## 한도의 성격

- **한도는 계정(API 키)당이다.** 여러 사이트가 같은 키를 쓰면 하나의 예산을 나눠 쓴다. 사이트를 늘려도 예산은 늘지 않는다.
- **한도는 "1분당 피크"로 걸린다.** 하루 총량이 적어도 몇 초 사이에 몰아서 호출하면 제한된다. "하루 총량에 여유가 있으니 빨리 돌리자"는 판단은 위험하다.
- 작성자가 2026-07 기준으로 확인한 쿠팡 측 한도는 검색 분당 50회, 리포트 시간당 500회, 전체 분당 100회, 링크 생성 분당 50회다. 경고 3회가 누적되면 이용이 제한되고, 한도를 넘기면 24시간 동안 기다려야 한다. 한도는 바뀔 수 있으므로 쿠팡 파트너스 공식 안내를 함께 확인한다.

## 운영 규칙

- **운영 상한**: 같은 키를 쓰는 모든 사이트를 합쳐 검색 호출을 분당 35회(쿠팡 한도의 70%) 이하로 유지한다.
- **단일 글로벌 throttle**: 모든 호출이 하나의 throttle을 거치게 하고, 최소 호출 간격 4초와 분당 하드캡 30회를 코드로 강제한다. throttle을 우회하는 호출 경로를 새로 만들지 않는다.
- **사이트 간 실행 시간 분리(stagger)**: 같은 키를 쓰는 사이트의 작업은 동시에 돌리지 않는다. 예를 들어 4시간 주기라면 사이트 A는 0분, 사이트 B는 120분에 시작하고, 사이트가 N개면 240÷N분 간격으로 나눈다.
- **초기 대량 등록도 throttle을 거친다.** 한 번에 몰아서 가져오지 말고 며칠에 나눠 등록한다.
- **403 응답이나 경고를 감지하면 즉시 전면 정지한다.** 예를 들어 `.coupang-api-paused` 같은 정지 표시 파일을 만들고, 모든 작업이 이 파일을 확인한 뒤 실행하게 한다. 쿠팡이 실제로 제한을 해제했다고 확인하기 전에는 호출을 재개하지 않는다. "해제될 예정"이라는 답변은 해제 확인이 아니다.
- **용량 계산**: 갱신할 수 있는 상품 수의 상한은 `35 × 갱신 주기(분)`이다. 4시간 주기라면 8,400개가 상한이고, 여유를 두려면 4,000개 정도를 권장한다. 사이트 개수는 안전과 무관하고 갱신 신선도만 좌우한다.

## 코드 검토 체크리스트

- [ ] 모든 쿠팡 API 호출이 하나의 throttle 함수를 거치는가
- [ ] 최소 간격 4초와 분당 30회 하드캡이 코드에 있는가
- [ ] 같은 키를 쓰는 예약 작업의 시작 시각이 겹치지 않는가
- [ ] 403과 경고 응답에서 정지 표시를 남기고 이후 호출을 막는가
- [ ] 재시도 로직이 한도를 우회하지 않는가(재시도도 throttle을 거치는가)
